听见校园：隐私优先的声景地图

把校园里的“安静、交谈、流动”转成可以观察和注释的视觉节奏。你可以先用合成样例体验，也可以授权本机麦克风做实时本地分析；标注与导出只留下相对强度和文字，不留下声音。

隐私面板不录制 · 不上传 · 不保存原始音频
  • 麦克风音频只在当前浏览器内实时分析，用于换算相对强度，不写入文件、不发往任何服务器。
  • 本作品不识别、不推断说话者身份，不做语音转写与说话人辨认。
  • 导出的 CSV / JSON 只含时段、场景、来源、相对强度与观察文字，不含任何音频内容。
  • 相对强度是 0–100 的相对值，不是校准分贝，不能作为噪声达标或健康影响结论。
  • 记录仅保存在当前页面内存中，刷新或关闭页面即清除。

处理位置。全部处理发生在你自己的设备上：Web Audio API 在本机读取音频振幅，按短时窗口换算为相对强度，随后该窗口的振幅数据即被下一次采样覆盖，不做留存。

身份与内容。程序只使用振幅的统计量，不分析语音内容，不识别或推断说话者身份，不做语音转写，也不建立任何与人物相关的档案。

麦克风控制权。你可以随时点击上方红色按钮立即停止分析并释放麦克风；浏览器标签页中的录音指示会随之熄灭。也可以改用合成样例模式，完全不索取麦克风权限。

数值边界。相对强度受设备型号、摆放位置、距离与环境的影响，未经过声学校准，不是声压级（dB SPL），不能用于噪声达标判定、环评结论或健康影响结论，也不构成对任何场地优劣的评价。

分类边界。“低 / 中 / 高相对强度”的分区阈值仅为本作品的交互演示规则，不是声学标准。

    作品说明

    1 · 作品简介与目标用户

    《听见校园：隐私优先的声景地图》是一个在浏览器本地运行的声景观察与可视化工具。它把校园中的声音活动转成可观察、可注释、可导出的视觉节奏，帮助使用者以“相对强度 + 场景 + 时段 + 文字观察”的方式记录身边的声环境。

    目标用户：做校园声环境观察的学生与社团、数字媒体与数据可视化课程的学习者、需要公开讨论声环境但不愿采集录音的公共空间管理者，以及希望了解“数据可以被怎样负责任地处理”的普通师生。

    2 · 创新点

    1. 隐私优先的本地处理。与常见的分贝 App 不同，本作品不录制、不上传、不保存原始音频。麦克风只在本机被用于实时振幅统计，采样窗口被下一次采样覆盖；导出物只有数值与文字。同时明确不识别、不推断说话者身份，不做语音转写，从机制上避免了对人物与对话内容的采集。
    2. 相对强度而非分贝的诚实表达。常见分贝 App 往往直接显示 dB 数值，容易让读者误以为其具备声学校准。本作品只给出 0–100 的相对强度，并在仪表、隐私面板与边界声明中反复说明它不是声压级、不能用于噪声达标或健康影响结论，用“克制”换取“可信”。
    3. 可注释的声景可视化。把单纯的数值曲线扩展为“记录—可视化—注释—导出”的闭环：每条观察都带时段、场景、来源与文字，进而形成实时曲线、记录柱状对比、场景分组统计三个视图，让个人感受与定量趋势一起成为可讨论的材料。

    3 · 数据来源与处理方法

    ① 数据来源。本作品不使用任何第三方数据集或音频素材库，页面不发起任何网络请求，全部数据在打开页面的这台设备上产生。

    • 合成样例（程序生成）：由程序内的确定性函数按帧序号 t 实时生成振幅统计量，不含真实录音、不读取麦克风。生成式：level = 18 + 10·sin(0.35t) + 7·sin(1.7t) + p(t)，其中 p(t) 在 t mod 34 大于 22 时为 42、在 14–22 之间时为 18、其余为 0；每 250 ms 取一帧，结果经四舍五入并截断到 0–100。
    • 本机麦克风（用户实时输入）：用户明确授权后，浏览器在本机读取麦克风音频并只用于实时分析；不留存原始音频、不写入任何文件、不上传服务器，也不读取任何外部音频文件。用户可随时「立即停止并释放麦克风」。
    • 示例记录（虚构演示数据）：作品提供 9 条虚构示例记录用于演示与录屏，在列表中标「示例」、导出时带 是否示例数据 标记，不来自任何真实观测，不应用于任何结论。

    ② 处理方法：从音频振幅到相对强度。

    1. 取时域振幅。Web Audio 的 AnalyserNode（fftSize = 1024）每 150 ms 取一次当前缓冲的 N = 1024 点时域数据 getByteTimeDomainData，得到取值 b ∈ [0, 255]。
    2. 归一化为有符号振幅。x_i = (b_i − 128) / 128，映射到 −1 ~ +1。
    3. 短时窗口 RMS。RMS = sqrt( (1/N) · Σ x_i² )。窗口长度 N = 1024 个采样点，按常见 44.1 kHz / 48 kHz 采样率换算约为 21–23 ms。
    4. 映射为相对强度。相对强度 = clamp( round( RMS × 280 ), 0, 100 )。系数 280 是为获得可读动态范围而设定的显示系数，未经任何校准。

    与声压级的区别（如实说明）：上述链路未做频率计权（如 A 计权）、未做时间计权（F / S），未做传声器灵敏度与频响校准，因此该 0–100 数值不是分贝（dB SPL），不能换算为分贝，不同设备之间的读数也不可直接横向比较。此外，每 150 ms 只取最近约 21–23 ms 的窗口，窗口之间存在间隔，属于抽样观察而非连续测量。

    ③ 信息结构：五个字段及其关系。每条记录是一个统一的数据单元，含五个字段：时段（早 / 午 / 晚）、场景（教学楼 / 食堂 / 图书馆 / 操场 / 宿舍 / 其他）、来源（合成样例 / 本机麦克风）、相对强度（0–100）、观察文字（≤ 120 字的用户主观描述）。其关系是：时段与场景是两条分类维度，决定记录在第三个视图中落在哪个分组；来源决定记录在第一、二视图中的配色与形状标记；相对强度是唯一的定量变量，承担三视图共用纵轴；观察文字承载无法被数值表达的情境，也是记录能被回忆与讨论的关键。五个字段全部可被导出，导出物不含音频。

    ④ 可视化逻辑：为什么是这三张图。三视图按“要回答的问题”分工，共用同一套纵轴定义（0–100、不随数据范围缩放）、同一套刻度步长（25）与相近的留白规则，使切换视图时刻度体系保持稳定。

    • 实时相对强度曲线（回答“随时间怎么变”）。时间连续、样本密集时，折线是最适合表达趋势的形状。视觉编码：横轴为时间窗口序号（左早—右新，共 80 个样本），纵轴为相对强度；2 px 青色折线加向下渐变填充表达走势走向，末端橙色圆点标出最新样本，背后三段背景色带连续映射为低 / 中 / 高三档，便于一眼判读所处区间。
    • 记录柱状对比（回答“条目之间谁更大”）。条目之间要做精确的横向比较，长度（柱高）是准确度最高的视觉通道，优于颜色或面积。视觉编码：横轴为记录序号（按添加顺序），纵轴为相对强度；柱례顶直接标注数值以避免读轴误差；来源用形状 + 颜色双重编码（合成样例 = 圆形、青色；麦克风 = 三角形、橙色）。
    • 场景分组统计（回答“哪里更吵”）。空间维度需要把多条记录压到一个分组里做聚合。视觉编码：横轴为场景分类轴（无序，等距），左纵轴为相对强度（平均值、最高值），右纵轴为记录条数；每组三根柱用实色 / 斜纹 / 点纹纹理区分序列，并在图下方提供同内容的文字统计列表，便于读屏与逐项核对。

    4 · 技术路线

    1. 取值。使用 Web Audio API：麦克风模式下由 getUserMedia 取得音频流，经 createMediaStreamSource 接入 AnalyserNode（fftSize = 1024），读取 getByteTimeDomainData 的时域振幅。
    2. 换算。对短时窗口内的振幅做 RMS（均方根）计算，再经线性映射并截断到 0–100，得到相对强度；合成样例模式由确定性函数生成演示序列，用于无麦克风时的体验。
    3. 信息结构。每条记录 = 时间 + 时段（早/午/晚）+ 场景（教学楼/食堂/图书馆/操场/宿舍/其他）+ 来源（合成/麦克风）+ 相对强度 + 观察文字，构成后续可视化与导出的统一数据单元。
    4. 可视化逻辑。三视图分工：实时曲线呈现“随时间的变化”，柱状对比呈现“条目间的横向比较”，场景分组统计呈现“空间维度的聚合”；三图共用一套配色与坐标规则（左轴固定 0–100 相对强度、刻度步长 25，场景图另设右轴记录条数），图例与坐标轴均标注清楚。完整的来源、处理方法、信息结构与编码规则见第 3 分区，坐标 / 配色 / 字号级的约束见第 5 分区。
    5. 工程约束。纯 HTML / CSS / 原生 JavaScript，无构建步骤、无外部依赖、无网络上传；所有图表由 Canvas 2D 代码直接绘制。

    5 · 可视化设计规范

    ① 配色系统。全站只使用一套主题色，同一颜色在所有视图中含义固定，避免跨图歧义。

    • 序列色：青色 #0b837e 用于主数据（实时曲线、平均值、合成样例来源）；橙色 #df795a 用于强调（最新样本、最高值、麦克风来源）；草绿 #8aa63f 用于第三序列（记录条数）。
    • 三档强度色带：低（0–28）#e8f2ec、中（29–61）#f2f3e2、高（62–100）#f7e6de。含义是把连续的相对强度离散为三档以便快速判读；这三个阈值只是本作品的演示规则，不是声学标准，在图表下方与隐私面板中均重复说明。
    • 中性色：纸白 #f7faf9、背景 #e5edf0、分隔线 #c4d2d4、网格 #d5e2df、正文墨 #18313a、次要文字 #63777d；危险操作（释放麦克风）用砖红 #a4382a，仅用于按钮。

    ② 坐标轴与网格。纵轴统一固定为 0–100 且不随数据范围缩放，保证跨视图与跨场次的可比性；刻度步长 25（0 / 25 / 50 / 75 / 100），刻度值紧贴轴的外侧标注。网格线 1 px #d5e2df，绘制于数据层之下；两条阈值分界线用 4:3 虚线 #b9cccb，弱于数据线。横轴为等距分类轴或时间序号轴，不做非线性压缩。三图的内边距（CSS 像素）分别为：实时图 左 40 / 右 96 / 上 16 / 下 24；记录图 40 / 16 / 28 / 26；场景图 40 / 40 / 28 / 26。画布按设备像素比重新取样，保证高分屏下线条与文字不虚。

    ③ 字号层级。页面主标题 clamp(31px, 4.6vw, 48px)；区块标题 15.5 px 与 12.5 px；正文基准 15 px，说明与列表 11.5–12 px，次要提示 10.5–11 px；图表的刻度、图例与元数据统一 9–10 px 等宽字体，保证数字对齐；中央读数 52 px 衬线体，作为唯一的视觉焦点。说明性段落行高 1.55–1.75，宽度受限以避免超长行。

    ④ 图例位置。图例统一置于绘图区顶部内侧：实时图在右上角（远离末端圆点所在的右上方数据时也保持不遮挡峰值），记录图与场景图在左上角；水平排布，随画布宽度自适应。图例项与数据序列使用同一种颜色、形状与纹理编码。

    ⑤ 空状态与加载态。

    • 空状态：无数据时仍绘制完整的坐标框架（轴线、刻度、轴标题），并在画布正中给出一句可操作提示（如“暂无记录，先在右侧添加一次观察”），不使用假数据填充；场景图空状态时，其下方的文字统计区同步显示为“暂无记录”。
    • 加载态：全部计算在本机同步完成、不发起网络请求，因此不设加载动画；进一步叠加何种视图也只由用户操作触发。

    ⑥ 无障碍与色盲友好性。作品不单靠颜色传达含义：来源使用形状（合成样例 = 圆形，麦克风 = 三角形），场景三序列使用填充纹理（平均 = 实色，最高 = 斜纹，条数 = 点纹），并始终辅以数值标注或文字列表。每张 canvas 都带描述其编码方式的 aria-label，关键数据另有文字版本（场景统计列表、最近样本分布百分比、逐条记录的元数据行）。所有交互元素可 Tab 聚焦并显示 3 px 橙色焦点环；选项卡支持左右方向键切换；抽屉支持 Esc 关闭并把焦点交还给触发元素；启用缅怀式减少动效偏好（prefers-reduced-motion）时不启用任何 CSS 过渡与动画（采样刷新属于数据更新，由用户启动并可随时停止）。

    6 · 操作与运行说明

    1. 直接用浏览器打开本 HTML 文件即可运行，无需安装与联网。
    2. 点击“播放合成样例”进入演示；点击“启用本机麦克风”进入实时分析。
    3. 麦克风前置条件：浏览器仅在安全上下文（HTTPS 页面或 localhost / 本地文件由浏览器策略决定）中提供 getUserMedia，且需要用户点击授权。若被拒绝或环境不支持，作品会自动降级为仅合成样例模式，并给出提示。
    4. 观察时选择时段与场景，填写观察文字后点击“添加记录”；可逐条删除或一键清空。
    5. 点击“导出 CSV”或“导出 JSON”保存记录；任何时候都可用红色按钮“立即停止并释放麦克风”。
    6. 演示路径：不想索取麦克风时，先点“播放合成样例”，再点右侧“载入示例记录”，三个视图会立即有内容可看；示例记录是虚构数据，随时可“清空示例”。

    7 · 展示与传播建议

    校园展览 / 开放日投屏。大屏循环展示合成样例下的实时相对强度曲线，同时把三视图依次切换播放：曲线讲“时间变化”，柱状图讲“条目比较”，场景图讲“空间聚合”。展示牌上必须写明“相对强度为 0–100 的相对值，不是分贝”，避免观众误读。展览结束时建议点一次“停止”，确认不再占用任何采集资源。

    科普活动 / 课堂互动。邀请观众自己添加一条观察：选时段与场景、写一句描述，柱状图会立刻多出一根属于他的柱子。活动结束前导出当天记录，把 CSV 或 JSON 做成“今天的校园声景”海报或图表；此时需注明数据来自现场观众的主观标注，并保留“示例数据”标记，不与真实观测混淆。

    课堂 / 工作坊使用。可用“载入示例记录”在几十秒内搭出完整三视图，用来讨论“同一份数据换一种图形会得到什么结论”，再对照本说明的数据方法分区检查每条结论是否有数据支撑。

    三个可以直接讨论的问题：

    1. 校园里哪些时段、哪些地点最“吵”？本作品的记录由个人在不同时间、不同设备上零星添加，样本量与覆盖都不均衡；要回答这个问题还缺什么？（同一时段多点位同步观察、足够多的重复样本、统一的设备摆位说明）
    2. 相对强度能代表“吵”吗？响度相近但频谱不同的声音（例如走廊里的人群说话声与食堂的餐具碰撞声）给人的感受很不一样；本作品只用了短时窗口的振幅统计，可视化有没有可能把这种差异表达出来？
    3. 隐私边界应该画在哪里？如果换成“能还原对话内容”的采集方式，即便同样宣称不保存音频，是否仍构成对个人信息的处理？“不录制、不上传”这一条约束，哪些环节最容易在实际改动中被悄悄放弃？
